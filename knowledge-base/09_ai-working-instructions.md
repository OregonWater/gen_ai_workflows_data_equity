## The premise

AI-assisted, not AI-dependent. The author owns the work. Session containers preserve reasoning; the knowledge base preserves current understanding.

## Before a session

Read 00, 01, and relevant pages; then the decisions register, project.yml, latest session, and project log. Inspect Git status. Do not silently reopen active decisions.

## While working

Discuss concepts before writing. Capture uncertain observations with status: open and provisional feeds. Do not let routing block capture.
Verify claims and citations; label uncertainty and interpretation. No substantive slide claim without an entry in 04.
Keep structural examples separate from research evidence. Use plain language and small, understandable changes.

## Data, copyright, and public records

Never commit data or restricted/nonredistributable material. Use registered sources and checked summaries.
Use nonpublic_notes/ for local private notes. Store no raw transcripts or extra session summaries.
Imported external AI notes need a source key and explicit verification status before assessment and reconciliation.

## Session close-out

1. Complete the dated session container with self-contained reasoning, decisions, reconciliation, and open threads.
2. Update affected pages and metadata.
3. Record decisions and a brief project-log entry; update project.yml.
4. Run provenance validation; render and inspect the site and deck.
5. Review Git status and exclusions. Commit only if explicitly requested; publication needs separate confirmation.

## AI assistance and authorship

Record assistance and model accurately; omit model for human-only sessions. Do not invent identifiers.
The author writes docs/how-this-was-made.md. Do not add AI co-author trailers to commits; document AI assistance in session records.
