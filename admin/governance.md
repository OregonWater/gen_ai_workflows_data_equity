## Four layers

| Layer | Purpose | Location |
| --- | --- | --- |
| Raw sources | Registered inputs to evaluate | references/sources.yml; local source files |
| Session containers | How understanding and decisions changed | sessions/YYYY-MM-DD.md |
| Knowledge base | Synthesized current understanding | knowledge-base/ and docs/ |
| Rendered site and deck | Browse and share the work | _site/ generated by Quarto |

project.yml is the present-state snapshot. Decisions and the project log retain rationale and history.

## Session rule

Every substantive knowledge-base change is traceable to a session. A session container is human-authorable and self-contained, with purpose, conceptual notes, decisions, reconciliation, and open threads. It is the session record; no raw transcripts or parallel session summaries are stored.

Capture an unrouted observation with status: open. Route and reconcile it when ready.
Public notes must be suitable for publication; candid nonpublic material stays in ignored nonpublic_notes/.

## Structural examples

Borrowed files supplied for setup inform structure and tooling only. They provide no research evidence, affiliation, or connection between projects. Original handoff briefs are retained in admin/template-repos/; additional example files remain external and untracked.

## Generated maps

Run `Rscript tools/build-provenance.R` from the root, or `quarto render`, which runs that check before rendering. The script checks registered keys, session references, feeds targets, component paths/status, and project state. It regenerates the following sections; substantive synthesis remains manual.
